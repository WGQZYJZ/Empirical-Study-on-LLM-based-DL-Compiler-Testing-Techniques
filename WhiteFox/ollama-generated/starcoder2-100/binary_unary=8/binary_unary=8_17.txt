## Solution
For this challenge the first solution that we found was by using `torch` functions to create the same output. Since we were not allowed to use these functions, and it would be very time consuming for us to modify a whole model in a single solution as we did (to create our modified version of the model), we focused on other tools. 

In our second solution, we wanted to use a custom model which was already given to us but we were not allowed to use it since this would be considered cheating. Therefore after some consideration, we decided that since the model was already given and we could not modify its parameters at all, we used a trick using `torch` operations without any external modules: 

- We created our custom model using `nn.Sequential()` which is basically like a vectorized version of `nn.Module`. This allowed us to create layers like `Conv2d` and `ReLU`, but no `LeakyReLU` as we did not have access to it. Since we were not allowed to modify the parameters in the model, we used the operations: `torch.Tensor` and `torch.Size` without any problems. For example, one of our ideas was that since the ReLU function takes a `tensor` as an input we could initialize a tensor with a given size (we did not need to use it because we directly used the size), then create a tensor of the size of that tensor, and then finally multiply them together without using a new tensor. 

- After that we applied the trick we described above by doing: 
    ```python
    output = input.size() * 30
    ```

In the final step, we used this output to run our LeakyReLU with a given slope of `0.25`: 
    
    
```python 
   return (input > 1e-4) * input + (input < -1e-4) * slope * ((1e-4 - input).abs()**3)
```
